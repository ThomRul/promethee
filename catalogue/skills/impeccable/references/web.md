# Critique web et renderer

Comparer hiérarchie, densité et contraste visuel au rôle de l'écran : le primaire est identifiable, les actions secondaires ne le concurrencent pas, les groupes correspondent au travail de l'utilisateur. Les espacements et tokens servent ces relations plutôt qu'un style uniforme de cartes.

Examiner les états concernés : vide, chargé, erreur, désactivé, succès ; libellés précis et navigation explicite. Vérifier redimensionnement, zoom, contenu long et focus lorsque les outils le permettent. L'accessibilité spécialisée traite le contrat clavier/ARIA ; éviter une seconde revue complète identique.

Une capture prouve ce qu'elle montre, pas un geste, une navigation ou un lecteur d'écran. Nommer les viewports et interactions effectivement exercés. Pas de dark mode, animation, nouvelles polices ou optimisation par mémoïsation ajoutés sans besoin.
